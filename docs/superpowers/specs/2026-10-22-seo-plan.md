# SEO plan for plutus-vm-bench.lantr.io (2026-10-22)

Goal: the page ranks in the top 10 for queries such as "Cardano Plutus VM benchmark", "Plutus
smart contract speed", "Cardano smart contract performance", "UPLC evaluator benchmark", "Plutus
Core CEK machine performance" and "Aiken vs Scalus performance".

Part 1 lists what the repo does now (on-page). Part 2 lists what the owner must do (off-page), in
order. On-page work alone does not rank a new domain: Google must first find the page (Search
Console, sitemap) and trust it (links from other sites).

## Part 1: on-page (implemented)

### Head (`report/template.html`, `seo_head()` in `report/generate_report.py`)

- Title, 59 characters: "Plutus VM Benchmark: Cardano smart contract evaluator speed".
- Meta description, about 155 characters, from the run: VM count, script count, run date.
  Example: "Cardano Plutus VM benchmark: 9 UPLC smart contract evaluators, decode + eval speed on 89
  scripts, checked against the Haskell CEK machine. Run 2026-11-01."
- Canonical, robots, author, theme-color `#09090f`, favicon `docs/favicon.svg`.
- Open Graph and Twitter card (`summary_large_image`). `og:image` is the absolute URL
  `https://plutus-vm-bench.lantr.io/og.png?v=<run date>`. The query string makes X, LinkedIn and
  Slack fetch the new image after each run; they cache images by URL.
- JSON-LD, one `@graph`: Organization Lantr (lantr.io), Person Alexander Nemish, WebSite,
  WebPage, Dataset and FAQPage. The Dataset has: description, keywords, creator (Lantr and
  Alexander Nemish), license (MIT), `dateModified` (the run date), `isBasedOn`
  (SAIB-Inc/cardano-plutus-vm-benchmark), and `distribution` with `unified.csv`, `gate.json` and
  `report.md` of the run on raw.githubusercontent.com (branch `main`). Google Dataset Search
  reads this.
- No BreadcrumbList: the site has one page, so a breadcrumb adds nothing.
- Google Fonts load with `<link rel="preconnect">` and `<link rel="stylesheet">`, not with
  `@import` in the CSS. An `@import` loads later and blocks the first paint longer.

### Canonical decision

- `docs/index.html` (the page at `https://plutus-vm-bench.lantr.io/`): canonical to itself,
  `robots: index, follow`.
- `results/<run>/index.html`: `robots: noindex`, no canonical. Reason: `run.yml` uploads only
  `docs/` to GitHub Pages, so a per-run copy has no URL on the site. Its content is the main
  page of that date, so it can only compete with the main page. A canonical to the main page
  together with `noindex` sends mixed signals, and Google ignores a canonical between pages with
  different numbers. The copy embeds its logo and favicon as data URIs, so it opens offline.
- The sitemap lists the main page only, for the same reason.

### Content that crawlers read without JavaScript

All of it is generated in Python from the same data as `report.md`. One list feeds both the
visible FAQ and the FAQPage JSON-LD, so the two are always equal.

- Intro paragraph under the header: what the page compares and why. It uses the key phrases in
  plain sentences: benchmark, Plutus virtual machines, UPLC evaluators, Cardano smart contracts,
  correctness gate, ExUnits, plutus-core, Haskell CEK machine, Cardano node.
- "Summary table" section after "Ranking": rank, VM, language / runtime, decode + eval geometric
  mean, eval-only geometric mean, "vs fastest" and the check verdict. The decode + eval column
  uses the penalty rule, like `report.md` and the overall ranking. Experimental VMs come last,
  marked "(experimental)" and "not ranked". The table is visible text, not hidden.
- "FAQ" section before the footer, 6 questions: What is a Plutus VM? What does this benchmark
  measure? Which Plutus VM is the fastest? (answered from the run data, with the note on
  execution models) Why does the ranking include the decode time? How often is the benchmark
  updated? How can a VM join the benchmark?
- Headings: one `h1` (the page title). The section titles are now `h2` with the same class, so
  they look the same (checked with before and after screenshots). The FAQ questions are `h3`.

Note: since 2023, Google shows FAQ rich results only for well-known government and health
sites. The FAQPage markup does no harm and other engines use it, but do not expect FAQ snippets
in Google. The FAQ text still helps, because it answers the queries in plain words.

### Static files for the published site

`generate_report.py --write-index` (only `run.yml` calls it) writes:

- `docs/robots.txt`: allow all, `Sitemap: https://plutus-vm-bench.lantr.io/sitemap.xml`.
- `docs/sitemap.xml`: the main page, `lastmod` = run date.
- `docs/og.png`, 1200x630: title and the five fastest ranked VMs with bars, run date, domain and
  Lantr logo. `og_card_html()` writes a small HTML card, and a headless Chrome takes a screenshot
  of it (`--headless=new --window-size=1200,630 --screenshot`). The script checks the PNG size.
  Chrome search order: `$CHROME`, `google-chrome`, `google-chrome-stable`, `chromium`,
  `chromium-browser`, the macOS app. The ubuntu-latest runner has `google-chrome`. Without
  Chrome (for example in `python:3.12-slim`) or on any failure, the committed `og.png` stays.
  Reason for this method: no Python dependency (`python:3.12-slim` has no Pillow), and text
  rendering in a pure-Python PNG writer is not worth the code.

`docs/favicon.svg` is a static, committed file.

The committed files are a start state, because the current `docs/index.html` is the old page of
2026-05-09: the sitemap has `lastmod` 2026-05-09 and `og.png` is a card without numbers. The first
publishing run replaces them.

`run.yml`: the "Commit results" step adds `docs/robots.txt docs/sitemap.xml docs/og.png` to the
commit with `docs/index.html`. The skip check of a scheduled run now also ignores
`docs/sitemap.xml` and `docs/og.png`; without this, every publish would make the next scheduled
run look like a code change.

### Performance and accessibility

- `html lang="en"` was already there. The page is now a `main` landmark.
- Logo: `alt="Lantr logo"`, `width="122" height="40"` (no layout shift when it loads).
- Links in the new intro, table caption and FAQ are underlined, not only coloured.
- Page weight: `docs/index.html` is about 90 KB for the 5-script fixture. A full run (9 VMs, 89
  scripts) adds about 70 KB of inline data (`unified.csv` rows and the eval-only timings), so
  about 160 KB, and about a quarter of that over gzip. Lighthouse total transfer on the fixture:
  162 KiB, most of it web fonts. Inline data is fine at this size.

### Validation (fixture runs 2026-10-22 and 2026-11-01)

- Both render in `python:3.12-slim` and with the host Python 3.9.
- Every `application/ld+json` block parses with `json.loads`. Each FAQ answer appears in the page
  as visible text, byte for byte.
- `node --check` passes on the page script.
- Headless Chrome: no console errors; `--dump-dom` contains the summary table rows.
- `xmllint --noout docs/sitemap.xml` passes.
- Lighthouse 13 (page served over `http://localhost`, default mobile settings): SEO 100, Best
  practices 100, Accessibility 96, Performance 89 to 98 between two runs (FCP 1.8 to 2.9 s under
  the simulated mobile network, mostly the web fonts).

Not fixed (outside this change, existing sections):

- The Pages artifact is all of `docs/`, so `docs/superpowers/specs/*.md` and
  `docs/IMAGE_CONTRACT.md` are served on the domain too, and `robots.txt` allows them. Thin
  internal pages on the same host do not help the main page. Owner decision: add
  `Disallow: /superpowers/` and `Disallow: /IMAGE_CONTRACT.md` in `write_site_files()`, or upload
  only the page files to Pages.

- Lighthouse "links rely on colour": links in the facts strip, the VM card notes and the footer.
- CLS 0.07: the facts strip is filled by JavaScript after the first paint. A fixed min-height or
  server-side text for the gate cell would remove it.
- `lantr-logo-dark.png` is 1224x400 (20 KB) for a 122x40 display. A 244x80 copy saves about 15 KB.

## Part 2: off-page actions for the owner (in this order)

### 1. Make the site live over HTTPS

GitHub Pages has never deployed (`status: null`). The Pages config is correct: `build_type:
workflow`, `cname: plutus-vm-bench.lantr.io`, `protected_domain_state: verified`, and the DNS
name is a CNAME to `lantr-io.github.io`. With `build_type: workflow`, `docs/CNAME` is not needed.

1. Wait for the scheduled run on 2026-11-01, or start `run` by hand with `publish: true`.
2. After the `pages` job is green, wait until GitHub has the TLS certificate (Settings > Pages
   shows it), then run:
   `gh api -X PUT repos/lantr-io/plutus-vm-benchmark/pages -F https_enforced=true`
3. Check: `curl -sI http://plutus-vm-bench.lantr.io/` returns 301 to `https://`, and
   `curl -s https://plutus-vm-bench.lantr.io/robots.txt` prints the robots file.

### 2. Google Search Console

`lantr.io` already has two `google-site-verification` TXT records. One of them may already
verify a Domain property for `lantr.io`, which covers all subdomains.

1. Open https://search.google.com/search-console and look for a property `lantr.io` (Domain).
2. If it exists in your account: go to step 5.
3. If not: Add property > Domain > `lantr.io` > copy the TXT value. Find out who owns the two
   old tokens before you add a third one.
4. Namecheap: Domain List > `lantr.io` > Manage > Advanced DNS > Add New Record > TXT Record,
   Host `@`, Value = the token, TTL Automatic > save. Back in Search Console, click Verify
   (DNS can take up to an hour).
5. Sitemaps > add `https://plutus-vm-bench.lantr.io/sitemap.xml` > Submit.
6. URL inspection > `https://plutus-vm-bench.lantr.io/` > Request indexing.
7. Check the structured data: https://search.google.com/test/rich-results and
   https://validator.schema.org with the live URL.

### 3. Bing Webmaster Tools (also feeds DuckDuckGo and Yahoo)

1. Open https://www.bing.com/webmasters and sign in.
2. Use "Import from Google Search Console": it imports the verified site and the sitemap.
3. If import is not possible: add the site `https://plutus-vm-bench.lantr.io/`, choose DNS
   verification, and add the CNAME record that Bing shows at Namecheap (Advanced DNS > Add New
   Record > CNAME Record, Host and Value as Bing gives them). Then submit the sitemap URL.

### 4. GitHub repository

```bash
gh repo edit lantr-io/plutus-vm-benchmark \
  --description "Benchmark of Cardano Plutus (UPLC) smart contract evaluators: speed and correctness of Haskell, Rust, Go, Scala and TypeScript VMs" \
  --homepage https://plutus-vm-bench.lantr.io \
  --add-topic cardano,plutus,uplc,untyped-plutus-core,benchmark,smart-contracts,cek-machine,aiken,scalus,performance
```

The homepage is already set. Pin the repository on the lantr-io organization page.

### 5. Links from own sites (the strongest first links)

1. scalus.org: link from the docs page about performance or the JIT, anchor text such as
   "Plutus VM benchmark" (source in the Scalus repo, `scalus-site/content/`).
2. lantr.io: a link from the home page or the projects page.
3. Scalus `README.md`: one line under the performance claims, "See the Plutus VM Benchmark at
   https://plutus-vm-bench.lantr.io".

### 6. Announce one time, after the first published run

1. Cardano Forum (https://forum.cardano.org), category Developers: what is measured, the
   correctness gate, how a VM can join, the link.
2. X: one post with `og.png` as the preview, tag the VM projects.
3. Reddit r/CardanoDevelopers (and r/cardano if the rules allow it).
4. Discord: the Aiken, Plutus and TxPipe developer channels, if they have a channel for tools.

### 7. Ask VM authors to link

Open an issue or a pull request in each VM repository that adds a "Benchmarks" line to its
README: Aiken (aiken-lang/aiken), blaze-plutus, Plutigo, uplc-turbo, plutus
(IntersectMBO/plutus). The README VM table has the repository links. Keep it short: the page, its correctness gate, and that the VM is
in it.

### 8. Cardano developer portal and lists

1. developers.cardano.org: fork `cardano-foundation/developer-portal`, add the benchmark to the
   builder tools showcase (a data entry and a screenshot; the portal's contribution guide names
   the files), and open a pull request.
2. Awesome lists on GitHub (search "awesome cardano"): add a line under tools or smart
   contracts.
3. Essential Cardano (IntersectMBO): suggest a link in the developer tools list.

### 9. Measure

After 4 to 6 weeks, check Search Console > Performance for the target queries. If the page shows
but has a low click rate, change the title or the description. If it does not show, more links
(steps 5 to 8) help more than more on-page work.
