This benchmark compares the speed of Plutus virtual machines (UPLC evaluators), the programs that run Cardano smart contracts. Each VM decodes and evaluates the same 89 Plutus scripts. A correctness gate checks every result and its execution units (ExUnits) against plutus-core, the Haskell CEK machine of the Cardano node. This run of 2026-10-23 has 9 evaluators, written in Go, Scala, Rust, Haskell, TypeScript and Scala.js. The method and the source are open.

History speed relative to Haskell plutus-core, same run – higher is faster

Each point is Haskell's geometric mean time divided by the VM's, from the same run: 2× faster means the VM needs half of Haskell's time. The solid grey line is Haskell (1×); a dashed line is an experimental VM. The ratio uses the scripts where both the VM and Haskell have a timing. A line marked “eval only” is a VM that compiles each script before timing: its ratio is its eval-only time divided by Haskell's eval-only time. Comparing ratios, not absolute times, removes most of the hardware and run-to-run drift. Servers of the same type differ: ratios to Haskell move up to about 5 % between two runs on different servers, so a change under 5 % is shown as no change. The end label and the tooltip give the change against the VM's previous run. Log scale.

Execution Model why categories matter

VMs differ in how they execute UPLC. A UPLC-level JIT compiler is doing fundamentally different work than a CEK interpreter, even when both happen to run on a JIT-compiled host runtime like the JVM or V8. Within-category numbers are like-for-like; cross-category numbers are not directly comparable.

Method

Two timings per script, eval only first. The ranking uses decode + eval: each iteration flat-decodes the script and evaluates it, as a node does with a script it has not seen. Eval only evaluates a program decoded once before timing; decoding is a large share of the time for some VMs (about 66 % for Haskell plutus-core), so the second column shows how fast the evaluator alone is.
Correctness gate: each VM evaluates every script once more and reports the result and the ExUnits. They must equal Haskell plutus-core; a VM that differs is not ranked (“failed check”). A VM whose API cannot take the mainnet cost model is ranked with an “outdated cost model” badge if it equals Haskell with the model the VM ships. A VM that compiles a script before it runs it (“decode and compile excluded”) decodes and compiles each script once, before timing; its timed loop runs the compiled script, so neither step is in its time. So it has only an eval-only time, shown only as eval only, and it is not ranked. Its compile time is shown separately. A VM whose library caches decoded programs (“decode cached (by the library)”) decodes a script only on the first call, in the warm-up; its timed loop runs the cache lookup and the evaluation, so its two columns have the same numbers.
Flat decode + evaluation on Plutus scripts. Each VM uses its native benchmark framework. Each VM runs in its own Docker image, one VM at a time. Geometric means within each category use only the scripts where every VM in that category produced a successful result, so all VMs in a category are compared on the same scripts.

FAQ Plutus VMs and this benchmark

What is a Plutus VM?

A Plutus VM, or UPLC evaluator, runs Untyped Plutus Core (UPLC), the language of Cardano smart contracts. The Cardano node uses the CEK machine of plutus-core (Haskell) to validate scripts. Wallets, SDKs, emulators and other tools use their own evaluators to compute the script result and its execution units (ExUnits) before they submit a transaction.

What does this benchmark measure?

Each VM flat-decodes and evaluates 89 Plutus scripts from the plutus-use-cases test suite (auction, escrow, uniswap, stablecoin and others). The page shows the mean time per script and the geometric mean over all scripts. Each VM runs in its own Docker image on the same server type, one VM at a time. A VM is ranked only if its results and ExUnits equal Haskell plutus-core on every script.

Which Plutus VM is the fastest?

In the run of 2026-10-23, Plutigo CEK (Go) has the lowest decode + eval geometric mean of the ranked VMs: 283.97 µs. plutus-core, the Haskell CEK machine of the Cardano node, takes 702.57 µs (2.47× the fastest time). The VMs use different execution models (CEK interpreter, AST walker, JIT compiler), so compare VMs of the same model too. Experimental VMs are not ranked.

Why does the ranking include the decode time?

A node decodes a script from its flat encoding before it evaluates it. For a script that the node has not seen, both steps take time. For some VMs the decode is a large share of the time (about 66 % for Haskell plutus-core), so the page also shows an eval-only time.

How often is the benchmark updated?

A GitHub Actions workflow runs the full benchmark on the 1st of each month, and the maintainers start extra runs when a VM release changes. The workflow skips a scheduled run when nothing changed. This page shows the run of 2026-10-23.

How can a VM join the benchmark?

A ranked VM has a published release, a downstream user today, and passes the correctness gate. Open a pull request that adds a Docker image for the VM. Follow CONTRIBUTING.md and the image contract.
